**Overview of Git and Version Control**  
- Git is a distributed version control system that allows multiple developers to work on the same project seamlessly.  
- Version control systems help in managing changes to code, enabling effective collaboration among team members.  
- The primary functions of version control are to share code effectively and manage different versions of files.

**Problems Addressed by Version Control Systems**  
- **Code Sharing**: In a collaborative environment, developers need to share their work without overwriting each other's contributions, which version control facilitates.  
- **Versioning**: Developers can track the history of changes made to files and revert to previous versions if needed, ensuring code stability and integrity.  
- These systems become crucial in large organizations with hundreds of files and multiple developers, where manual sharing of code becomes impractical.

**Difference Between Centralized and Distributed Systems**  
- Centralized version control systems, like SVN, require all developers to connect to a single server, which can lead to issues if the server goes down.  
- In contrast, Git operates as a distributed version control system, allowing developers to work independently on their local copies and share changes with others.  
- This structure enhances collaboration and reduces risks associated with a single point of failure in centralized systems.

**Understanding Git vs. GitHub**  
- Git is the core version control tool, while GitHub is a hosting service that provides a user-friendly interface and additional features like project management and collaboration tools.  
- Git can be used independently of GitHub, but GitHub builds on Git’s functionality, allowing for better usability and community interaction.  
- Other platforms like GitLab and Bitbucket also utilize Git but offer their unique features and enhancements.

**Essential Git Commands**  
- **git init**: Initializes a new Git repository in the current directory.  
- **git add**: Stages changes in the working directory for the next commit.  
- **git commit**: Saves the staged changes to the repository, creating a new version of the project.  
- These commands form the basic workflow for developers to track and manage their code changes effectively.

**Workflow Example**  
- A developer creates a file, stages it using `git add`, and commits it with `git commit`.  
- The developer can review the history of changes using `git log` and can revert to earlier versions as necessary.  
- Sharing code is achieved by pushing local changes to a remote repository on platforms like GitHub, enabling collaboration with other team members.
